## Name

**Mode B — Mid-TF structure for short-term / scalp setups.**

## Problem it would address (future, if ever started)

Mode A (the current frozen product) builds structure on HTF (H4 + H1 required,
W1 + D1 optional context) and executes on M5; setup volume is a direct function
of how often HTF structure forms. For identification/validation work one may
also want a complementary, **smaller-Bar TF structure path** with its own
higher-volume setup population — useful for examining SMC building blocks
(OB / FVG / demand-supply) under more frequent formation conditions.

## Mode A vs Mode B (canonical contrast)

| | Mode A (CURRENT FROZEN product) | Mode B (FUTURE, NOT STARTED) |
|---|---|---|
| Structure TFs | H4 + H1 required; W1 + D1 optional context | M30 and/or M15 may emit POI (OB, FVG, demand/supply) |
| Execution TF | M5 | M5 and/or M1 (TBD) |
| Flow | HTF POI → HTF-linked interaction → LTF confirm | mid-TF POI → sweep of that zone → lower-TF confirm (M5/M1) → plan |
| Purpose | current frozen product path | higher setup count for identification validation of SMC building blocks |
| Relationship to Mode A | the product | separate track; not an excuse to retune Mode A |

## Flow (Mode B, conceptual only)

1. Detect POI on M30 and/or M15 (OB, FVG, demand/supply).
2. Record a sweep of that mid-TF zone.
3. Wait for lower-TF confirmation (M5/M1).
4. Form a plan (entry/SL/TP/TARGET) from that confirmation.

This is a **concept**, not a spec. No constants, no geometry, no triggers
defined here.

## Hard rules (if it is ever started)

1. **Separate funnel/ledger from Mode A.** Mode B evidence must be a separate
   setup population from Mode A; never pool trades across modes to claim edge.
2. **No Mode A retuning.** Mode B existence is not an excuse to retune
   Mode A thresholds. Mode A stays frozen unless there is a dated ruling.
3. **Identification/validation framing.** The initial purpose is identification
   validation of SMC building blocks, not live expectancy proof.
