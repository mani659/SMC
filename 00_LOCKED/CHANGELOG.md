### 2026-10-08 (2) — Heartbeat WinError 5 on atomic replace fixed (EA + Python coexistence; pack v1.1-test.7)
- **Live evidence:** `HEARTBEAT WRITE FAILED: replace smc_heartbeat.txt.tmp -> smc_heartbeat.txt [WinError 5] Access is denied` → EA alerts "Python heartbeat stale (6s/36s)" → session fail-closed `ABORT: heartbeat publication failed` (exit code 3). - **Root cause (confirmed):** the watchdog EA opens, reads line 1, and `FileClose`s the heartbeat each 1 s timer tick; when that read overlaps Python's atomic rename (`os.replace`), Windows refuses the rename (the target is held without delete-sharing). ~1 collision in 175 publishes was enough to trip the old "raise on any OSError" path.

Only when the temp write, every rename attempt, and the in-place fallback all fail does it raise `HeartbeatWriteError` — a single transient collision no longer aborts the session; a persistent total failure still fails closed. Retry timing is operational (not a locked constant).
- **EA:** already opens, reads line 1, and closes every tick — NO EA change needed.
- **Tests:** +3 in `test_perm_hardening.py` (transient lock recovers via retry; persistent lock falls back in-place with a warning; total failure raises carrying target + both errors). Suite **914 → 917 passed**; `locked_constants.py` diff empty.
